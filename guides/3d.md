# Choosing 3D

`ux-find` reads this for any 3D or WebGL request. **Step 0** decides whether 3D is justified at all.
**Step 1** picks the form. **Step 2** picks the library from `SOURCES.md` (`3d`) and the profiles in
`sources/` (every library did the same four tasks with the same model; see `bench3d/`). **Step 3** lists sensible defaults: start from them, and depart when the situation calls for it.

## 0. Should this be 3D at all?
3D costs 150–850 KB of JavaScript, megabytes of assets, battery, and accessibility work, so it should earn its
place. It usually does when it shows something 2D can't; a deliberate brand moment can also justify it (see the
Stripe and GitHub examples):

| Use 3D when… | Don't, use 2D, video or images when… |
|---|---|
| Shape, scale or material is the point (a product people would turn over in their hands) | It's decoration behind text |
| The user configures something visual (colour, parts, size) | A 6-second loop would say the same thing (use a video) |
| Spatial relationships matter (a floor plan, an assembly, a route) | The content must be read, compared or scanned |
| One signature brand moment, done well | Every section "needs to feel premium" |

## 1. Form: what is the 3D doing?
| Job | Form | Notes | Example in the library |
|---|---|---|---|
| Show one product | **Product viewer**: orbit, soft shadow, hotspots, AR on phones | Poster first; drag hint; no auto-rotate with reduced motion | `3d/modelviewer-hotspot-annotations` |
| Let users customise | **Configurator**: viewer + swatches that swap materials | Controls are normal HTML buttons, not 3D | none yet |
| Hero or brand moment | **Hero scene**: one model or abstract form, subtle pointer parallax | Headline stays HTML and readable over it; consider a static poster on mobile if heavy | `3d/stripe-webgl-ribbon-hero`, `3d/github-floating-characters-hero` |
| Tell a story while scrolling | **Scroll-driven scene**: camera or model moves with scroll | Keep the text in HTML; scene is illustration | `3d/igloo-scroll-webgl-story`; without WebGL: `3d/apple-airpods-scroll-story` |
| Data in space (globe, network) | **3D data view** | Usually worse than 2D; justify it | none yet |
| Decorative motion | **Shader background** | Small (OGL) where possible; pause off-screen; consider stopping for reduced motion | `3d/stripe-webgl-ribbon-hero` |

Also in the library: `3d/bruno-simon-drivable-portfolio`, an immersive experience where exploration is the point.

**What the six example sites show** (captured live, see each `evidence.json`):
| Site | Engine | Transferred | Stops for reduced motion | Canvas accessibility |
|---|---|---|---|---|
| Stripe hero | three.js r178 | ~2.7 MB | No | `aria-hidden` (decorative) ✓ |
| GitHub hero | three.js r148 | ~4.7 MB | Yes ✓ | Unlabelled |
| model-viewer demo | model-viewer (three r183) | ~3.3 MB | No (demo page) | Hotspots are buttons ✓ |
| Apple AirPods | Video + images, no engine | ~4.8 MB | Yes ✓ | Real HTML + media controls ✓ |
| Bruno Simon | three.js r183 | ~7.5 MB | No | Unlabelled, no `<h1>` |
| Igloo | three.js r165 | ~15 MB | No | Canvas hidden from the DOM, no `<h1>` |

Even best-in-class sites usually skip reduced motion and canvas labels, so the defaults below are where we can do better than the references.

## 2. Library: which source fits the job?
Overall scores are in `SOURCES.md`; **fit beats score**. Start from the first row that matches.

| If the job is… | Use | Score | Why (evidence) | Runner-up |
|---|---|---|---|---|
| Show one product in 3D (product page, launch, docs), maybe AR | **model-viewer** | 7.5 | One tag; best out-of-box look; keyboard + alt + button hotspots built in | React Three Fiber |
| Any custom scene in our React/Next app (hero, configurator, scroll story) | **React Three Fiber + drei** | 8.5 | Best look for least code; `<Html>` hotspots, ContactShadows, Instances; React 19 | three.js |
| Custom scene outside React, or tight render-loop control | **three.js** | 7.3 | The engine itself; 160 KB gz tree-shaken | React Three Fiber |
| A 3D application (simulator, twin, XR, editor) | **Babylon.js** | 7.0 | Full engine, keyboard camera by default; 846 KB gz | three.js |
| A tiny shader effect where every KB counts | **OGL** | 5.8 | 25 KB gz; you write the shaders | three.js |

## 3. Defaults (guidance, not rules)
Good starting points drawn from the benchmark and the example sites. Each has a reason; when the reason doesn't
apply, depart from it and say why.

| Default | Why | When to depart |
|---|---|---|
| Poster first, then lazy-load the 3D (`next/dynamic(..., { ssr: false })`) when it scrolls into view | WebGL shouldn't delay the first paint or the headline | The 3D *is* the product (a configurator page, an immersive experience): load it early, but keep a designed loading state (Bruno Simon, Igloo) |
| About 2 MB of assets per scene on mobile; compressed glTF (Draco/Meshopt, KTX2) | Download and decode time dominate on phones | Experiences people choose to enter (games, showcases) can be far heavier: Igloo transfers ~14 MB. Show progress |
| Self-host environment maps and models | Runtime CDN fetches add a dependency you don't control | Prototypes and internal demos |
| Render only when something changes; cap DPR at 2; pause off-screen | Battery and heat on laptops and phones | Continuously animated scenes, where you still pause off-screen |
| Stop auto-motion under `prefers-reduced-motion` | Motion can cause discomfort | Slow ambient motion may be acceptable if it's subtle; test it. Most example sites we captured kept animating |
| A text alternative for the canvas and real HTML controls | Canvases are invisible to screen readers and often keyboard-unreachable | Purely decorative backgrounds can be `aria-hidden` |
| Keep essential information in HTML, not only in 3D | Search, translation, accessibility | Games and art pieces where the 3D is the content |
| Leave colour management to the library (sRGB output) | glTF colours are linear | Custom shaders (OGL) where you handle it yourself |
| Test on a real mid-range phone | Our timings come from a software GPU | None |

Not every 3D look needs real-time 3D: Apple's AirPods page gets its 3D product story from video and image
sequences (see `3d/apple-airpods-scroll-story`).
