## Interface review: Ledgerly pricing page

### Scope and coverage

**Scope.** All of `benchskills/fixtures/seeded-pricing.html` (132 lines, one static screen): header, banner, ticker, hero, plan cards, comparison table, about copy, newsletter form, the inline "Delete workspace" dialog, fine print, FAQ and footer. I looked at it at 1280px, 320px, and 640px (equal to 1280px at 200% zoom). There is no loading state, and the only empty or error content is the two static error lines. I did not check dark mode (the page defines none) or RTL (the page is `lang="en"`). Nothing was excluded for size.

**Stack.** Plain HTML with one inline `<style>` and one empty inline script. There is no framework, component library or build. Colours are hard-coded hex; only `--ink`, `--bg` and `--accent` exist as variables. All fixes are plain CSS or HTML.

**Project convention documents.** None for this page: no CONTRIBUTING, CODING_STANDARDS, AGENTS, design-system doc, Storybook or ADR. The repo-level `CLAUDE.md` covers the library, not this interface, so no convention excuses any finding.

### Considered and not reported

- **Button styling.** Four treatments exist: `.choose` (4px radius), `.btn-primary` (6px), the unstyled dialog buttons and the square `.banner-close`. `.choose` and the dialog buttons also fall back to 13.3px because buttons do not inherit font size. This is real, but the 15-row cap made me drop it as the lowest-impact item. Fix it with one shared button rule.
- **Footer links.** They are 12px, 14px tall and 6px apart. They pass the WCAG 2.5.8 spacing exception (I checked the 24px circle), so this is a density choice, not a failure.
- **`href="#"` on "Sign in" and the footer links** looks like fixture scaffolding, not a design problem.
- **Physical `left`/`right` properties.** Not reported, because nothing on the page needs RTL.
- **Billing copy.** The fine print mentions "Annual plans" but only monthly billing is offered. I could not tell if that is intended, so I did not rank it.

### Verification

Run, in Playwright with Chromium headless on a file URL:

- Contrast for 13 text and border pairs from computed colours, using the WCAG 2 formula. The hero lede was measured against screenshot pixels with its own text hidden.
- Tab order over 22 presses at 1280px: FAQ, Pricing, Sign in, close button, three "Click here", input, Submit, OK, Cancel, two summaries, five footer links, then the cycle repeats. The compare "link" never took focus. Every stop except the summaries had `outline-style: none`.
- CDP `Accessibility.getFullAXTree`: the close button name is empty, three buttons are named "Click here", the input is named only from its placeholder, there is no main or nav landmark, and headings run h1, h4 ×3, h2, h3, h2.
- Ticker transform sampled over time, then again with `reducedMotion: 'reduce'`. It kept moving.
- `scrollWidth` and per-element overflow at 320px (584px) and 640px (640px, no overflow).
- Plan hover: Starter did nothing; Business shrank from 438px to 266px.
- Anchor jumps under the sticky header: `#plans` and the Compare click.

**Not verified:** pinch-zoom blocking on a real touch device (the headless run only reports the meta content); real screen-reader speech (I read the accessibility tree instead); browsers other than Chromium; whether Impact, Comic Sans MS and Georgia exist on the reader's machine (I reviewed the declarations).

### Verdict

**Block.** Ten HIGH findings remain (rows 1 to 10). Every domain was inspected, so none is `Not reviewed`.
